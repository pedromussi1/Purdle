# Purdle

A small platform of daily word puzzles — every puzzle generated by an automated pipeline of an LLM and classical ML, with **no human in the loop**.

> **Live:** https://purdle.app/

![Purdle in play — a three-guess solve of today's automatically-generated puzzle](docs/screenshot.png)

Four games today, room for more:

- **Purdle** (`/play`) — a faithful five-letter Wordle-style puzzle: 6 guesses, green / yellow / grey feedback, hard mode, color-blind palette, dark mode, in-browser information-theoretic solver, archive of past puzzles with replay mode, shareable emoji grid.
- **Quartet** (`/quartet`) — sort 16 words into 4 themed groups of 4, with at most 4 mistakes. Tier-coloured reveals (yellow → purple), "one away" feedback, in-browser cosine-similarity hint over per-puzzle embeddings, share grid.
- **Ladder** (`/ladder`) — Lewis Carroll's Word Ladder: chain a start word to a target by changing one letter at a time. BFS-shortest path counted as the optimum to chase. Per-step letter-change highlight, give-up reveals the optimal path.
- **Synonymy** (`/synonymy`) — chain a start word to a target through *semantic* neighbours instead of letter changes. Each successive word must have embedding cosine similarity ≥ 0.5 to the previous one. Players literally walk through the embedding space.

Optional sign-in (Google or GitHub OAuth) syncs stats across devices via Supabase + Postgres + Row Level Security; not signing in is fully supported and stats stay in localStorage.

The interesting part is everything *behind* the puzzles.

## Why this exists

Most Wordle / Connections / Ladder / Synonym-chain clones rely on a hand-curated answer list and a human editor. Purdle replaces that editorial step with four reproducible automated pipelines running on free GitHub Actions:

```
                        ┌──────────────────────────────────────────┐
                        │  GitHub Actions cron — daily, UTC        │
                        │  Purdle: 00:05 · Quartet: 00:10          │
                        │  Ladder: 00:15 · Synonymy: 00:20         │
                        └──────────────────┬───────────────────────┘
                                           │
                                 ┌─────────▼─────────┐
                                 │  Gemini 2.5       │
                                 │  Flash-Lite       │
                                 └─────────┬─────────┘
                                           │
              ┌──────────────────────────────────────────────────────────┐
              │   Per-game validation pipeline (see tables below)        │
              │   wordfreq · profanity · curated dictionary ·            │
              │   embedding novelty (Purdle) · embedding clustering      │
              │   (Quartet) · BFS over common-words graph (Ladder) ·     │
              │   BFS over precomputed synonym graph (Synonymy) ·        │
              │   recency / theme / pair dedup                           │
              └──────────────────────────┬───────────────────────────────┘
                                         │
                                         │  Reject? feed reason back into
                                         │  next prompt (up to 5 retries)
                                         │  — else fall back to a
                                         ▼  deterministic / curated pick
                              ┌──────────────────────┐
                              │  YYYY-MM-DD.json     │
                              │  committed to repo   │
                              └──────────┬───────────┘
                                         │   workflow_run trigger
                                         ▼   redeploys Pages
                              ┌──────────────────────┐
                              │  GitHub Pages        │
                              │  (purdle.app)        │
                              └──────────┬───────────┘
                                         ▼
                                  Browser fetches
                                  today's puzzle
```

Every external dependency (Gemini, the embedding model, even the `wordfreq` and `better-profanity` libraries) is optional. If any one fails or isn't installed, the script falls back to a deterministic SHA-256-of-date pick from a curated source — answer list (Purdle), backup puzzle set (Quartet), or random reachable answer-list pair (Ladder). The site always has a puzzle to serve.

## The validation pipelines

Each game's pipeline runs the same retry-with-feedback loop but with checks tuned to its puzzle shape.

### Purdle (single 5-letter answer)

| Check | Library | Reject when |
|---|---|---|
| Format | stdlib regex | Not exactly five lowercase letters |
| Recency | stdlib | Appeared in the last 30 puzzles |
| Curated dictionary | stdlib | Not in `scripts/answer_list.txt` |
| Profanity | `better-profanity` | Flagged as a slur or vulgarity |
| Frequency | `wordfreq` | Zipf score < 3.5 (too obscure) |
| Novelty | `sentence-transformers` | Cosine similarity > 0.75 vs any of the last 30 solutions |

### Quartet (16 words → 4 themed groups)

| Check | Library | Reject when |
|---|---|---|
| Shape | stdlib | Not exactly 4 groups of 4 words; tiers 1-4 not all present |
| Word format | stdlib regex | Not 2-12 lowercase letters; duplicates across groups |
| Profanity | `better-profanity` | Any word flagged |
| Frequency | `wordfreq` | Any word's Zipf score < 3.0 |
| Theme recency | stdlib | Theme reused in last 30 puzzles |
| **Cluster cohesion** | `sentence-transformers` | Mean intra-group cosine similarity < 0.20 *(group's words don't actually cluster)* |
| **Cluster separation** | `sentence-transformers` | Centroid-to-centroid similarity > 0.65 between any two groups *(themes overlap too much)* |

### Ladder (start word → end word, one letter at a time)

| Check | Library | Reject when |
|---|---|---|
| Format | stdlib regex | Either word isn't exactly five lowercase letters |
| Identity | stdlib | Start equals end |
| Membership | stdlib | Either word is missing from the dictionary |
| Recency | stdlib | (start, end) pair appeared in the last 30 puzzles |
| **Reachability** | stdlib BFS | No chain of one-letter mutations connects start to end |
| **Common-words optimum** | `wordfreq` + BFS | BFS-shortest path through Zipf ≥ 3.5 words is shorter than 3 or longer than 7 steps |

### Synonymy (start word → end word, through semantic neighbours)

| Check | Library | Reject when |
|---|---|---|
| Format | stdlib regex | Either word isn't exactly five lowercase letters |
| Identity | stdlib | Start equals end |
| Graph membership | stdlib | Either word isn't in the precomputed synonym graph |
| Recency | stdlib | (start, end) pair appeared in the last 30 puzzles |
| **Semantic reachability** | stdlib BFS over `sentence-transformers` adjacency | No chain through cosine-similarity ≥ 0.5 neighbours connects start to end |
| **Optimum length** | BFS | Shortest path through the synonym graph is shorter than 3 or longer than 7 steps |

Synonymy uses a **precomputed adjacency list** built once by `scripts/build_synonymy_graph.py` (committed to `public/words/synonymy-graph.json`). The daily generator and the browser both consume the same graph; embeddings themselves never run at request time. Rebuild the graph with the manual `Build synonymy graph` workflow when the dictionary or threshold changes.

The Quartet cluster check, the Ladder common-words BFS, and the Synonymy embedding-graph BFS are the headline ML / classical-CS techniques on top of Purdle's per-word novelty: they validate **structural** properties of the LLM's output, not just per-word ones. When a candidate fails, the rejection reason gets fed back into the next prompt attempt.

## In-game ML and algorithms (client-side)

| Game | Feature | Technique |
|---|---|---|
| Purdle | "Solver hint" button shows the entropy-maximising next guess | Brute-force `expectedInfoGain` over the ~14k valid-guess list against the filtered candidate set; precomputed `SALET` opener (≈5.88 bits) for instant turn-1 feedback |
| Quartet | "Solver hint" button suggests the next pick most semantically tied to current selection | Cosine similarity over per-puzzle word embeddings (16 × 384-dim MiniLM vectors, lazy-loaded as a JSON sidecar) |
| Ladder | "Give up" reveals the optimal path with the changed letter highlighted at each step | Optimal path is precomputed in CI by Python BFS over the common-words graph; client only needs to render |
| Synonymy | **Real-time embedding-similarity validation** as the player types | Precomputed adjacency lookup (`public/words/synonymy-graph.json`, ~50 KB) shipped to the browser; each submitted word is checked synchronously against the previous word's neighbour list. Players literally interact with the embedding space. |

All three run **entirely in the browser**, no server round-trip — auditable math and zero API budget.

## Tech stack

| Layer | Choice |
|---|---|
| Frontend | React 19 + Vite + TypeScript (strict), React Router 7 |
| State | Zustand with `persist` middleware. Per-game store factory + React-context provider so the same UI works for both the persisted "today" instance and ephemeral archive replays |
| Auth & cloud sync | Supabase (Google / GitHub OAuth), Postgres + Row Level Security per user. Opt-in; gracefully degrades to local-only when env vars aren't set |
| Styling | CSS variables + tokens, no UI framework |
| Tests | Vitest — `evaluate.test.ts` covers Purdle's duplicate-letter algorithm + hard-mode rule; `solver.test.ts` covers the entropy / pattern grouping |
| Pipelines | Python 3.12, Gemini 2.5 Flash-Lite, `wordfreq`, `better-profanity`, `sentence-transformers` |
| CI / Cron | GitHub Actions (unlimited minutes for public repos) — `daily-puzzle.yml`, `daily-quartet.yml`, `daily-ladder.yml`, `daily-synonymy.yml`, plus a one-shot `build-synonymy-graph.yml` that recomputes the synonym adjacency list. `deploy.yml` is `workflow_run`-triggered by all of them |
| Hosting | GitHub Pages on a Cloudflare-registered custom domain (purdle.app) |

Total runtime cost: **$15/year** for the domain. Pages, Actions, Gemini Flash-Lite, and Supabase all stay on free tiers.

## Run locally

### Frontend

```powershell
npm install
npm run dev          # http://localhost:5173/
npm test             # Vitest
npm run build        # tsc --build && vite build
```

### Pipelines

All four generators run without any Python deps using their deterministic-fallback paths — useful for local development:

```powershell
python scripts/generate_puzzle.py   --date 2026-05-06
python scripts/generate_quartet.py  --date 2026-05-06
python scripts/generate_ladder.py   --date 2026-05-06
python scripts/generate_synonymy.py --date 2026-05-06   # needs synonymy-graph.json
```

For the full LLM-driven pipelines, set up a venv and provide a Gemini API key:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r scripts/requirements.txt
$env:GEMINI_API_KEY = "<your-key>"
python scripts/generate_puzzle.py   --date 2026-05-06 --force
python scripts/generate_quartet.py  --date 2026-05-06 --force
python scripts/generate_ladder.py   --date 2026-05-06 --force
python scripts/generate_synonymy.py --date 2026-05-06 --force
```

The Synonymy generator depends on `public/words/synonymy-graph.json` (the precomputed adjacency list). It's committed to the repo, but if you ever change the dictionary or want to retune the threshold, regenerate it with `scripts/build_synonymy_graph.py` (heavy — embeds ~5 k words via `sentence-transformers`, ~2 min on CI).

Get a free Gemini key at https://aistudio.google.com/apikey. Free tier (≈ 1,000 RPD on Flash-Lite) is well over what these pipelines need.

### One-time setup

```powershell
.\scripts\download_word_lists.ps1   # Purdle answer list + valid-guess dictionary + Ladder bridge augmentations
```

The downloader also merges `scripts/extra_words.txt` into the valid-guess dictionary — a small list of recognisable proper-noun-derived adjectives (`norse`, `greek`, `roman`, `latin`, `dutch`, …) the upstream Wordle list excludes. They're useful as bridge words in Word Ladder chains.

If you want cloud-synced stats, also create a Supabase project and apply all SQL migrations from `supabase/migrations/`. The repo's `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` GitHub Actions secrets feed those values into the build at deploy time.

## Repo layout

```
src/games/purdle/               # Purdle game (Wordle-style 5-letter)
src/games/quartet/              # Quartet game (16 words → 4 groups)
src/games/ladder/               # Ladder game (chain start → end, one-letter changes)
src/games/synonymy/             # Synonymy game (chain start → end, semantic neighbours)
src/shared/                     # game-agnostic platform shell:
                                #   Header, Modal, settings store, auth store,
                                #   Supabase client, date helper
src/pages/                      # platform-level routes:
                                #   Home, NotFound, archive + replay per game
public/puzzles/<game>/<lang>/   # daily puzzle JSON + manifest (committed by cron)
public/words/                   # valid-guess dictionary, Purdle answer list,
                                #   synonym adjacency graph
scripts/                        # generators + bootstrap + word-list downloader + extras
supabase/migrations/            # 0001 wordle_stats, 0002 quartet_stats,
                                #   0003 ladder_stats, 0004 synonymy_stats
.github/workflows/              # deploy.yml + daily-puzzle.yml + daily-quartet.yml +
                                #   daily-ladder.yml + daily-synonymy.yml +
                                #   build-synonymy-graph.yml (one-shot)
```

### Adding a new game

The shell is designed to host more games. To add e.g. a crossword:

1. Create `src/games/crossword/` with its own page, components, store factory, types.
2. Add `/crossword`, `/crossword/archive`, `/crossword/archive/:date` routes in `src/App.tsx` and the corresponding modal switch in the route-aware `Shell`.
3. Build a parallel `scripts/generate_crossword.py` that writes to `public/puzzles/crossword/<lang>/<date>.json` (the `lang` field on the puzzle schema is forward-compatible — additional languages slot in as `crossword/es/`, etc.).
4. Add a sibling `daily-crossword.yml` workflow and add it to the `workflow_run` trigger in `deploy.yml`.
5. (Optional) `supabase/migrations/0004_crossword_stats.sql` mirroring the existing patterns.
6. Add a card to `src/pages/Home.tsx`.
