# Purdle

A small platform of daily word puzzles — every puzzle generated by an automated pipeline of an LLM and classical ML, with **no human in the loop**.

> **Live:** https://pedromussi1.github.io/Purdle/

![Purdle in play — a three-guess solve of today's automatically-generated puzzle](docs/screenshot.png)

Two games today, room for more:

- **Purdle** (`/play`) — a faithful five-letter Wordle-style puzzle: 6 guesses, green / yellow / grey feedback, hard mode, color-blind palette, dark mode, in-browser information-theoretic solver, archive of past puzzles with replay mode, shareable emoji grid.
- **Quartet** (`/quartet`) — sort 16 words into 4 themed groups of 4, with at most 4 mistakes. Tier-coloured reveals (yellow → purple), "one away" feedback, archive + replay, all the same shell features (dark mode, color-blind, sign-in, etc.).

Optional sign-in (Google or GitHub OAuth) syncs stats across devices via Supabase + Postgres + Row Level Security; not signing in is fully supported and stats stay in localStorage.

The interesting part is everything *behind* the puzzles.

---

## Why this exists

Most Wordle clones rely on a hand-curated answer list and a human editor; most Connections-style clones rely on someone manually authoring 4 themed groups every day. Purdle replaces both editorial steps with a reproducible automated pipeline running on free GitHub Actions:

```
                        ┌──────────────────────────────────────────┐
                        │  GitHub Actions cron — daily, UTC        │
                        │  Purdle: 00:05  ·  Quartet: 00:10        │
                        └──────────────────┬───────────────────────┘
                                           │
                                 ┌─────────▼─────────┐
                                 │  Gemini 2.5       │
                                 │  Flash-Lite       │   (proposes a word OR
                                 │                   │    16 words in 4 groups,
                                 └─────────┬─────────┘    JSON-strict)
                                           │
                                           ▼
              ┌──────────────────────────────────────────────────────────┐
              │   Validation pipeline (per game; see tables below)       │
              │   Word frequency · profanity · curated dictionary ·      │
              │   embedding novelty (Purdle) · embedding clustering      │
              │   (Quartet) · recency / theme dedup                      │
              └──────────────────────────┬───────────────────────────────┘
                                         │
                                         │  Reject? feed reason back into
                                         │  next prompt (up to 5 retries)
                                         │  — else fall back to a
                                         ▼  deterministic date-hash pick
                              ┌──────────────────────┐
                              │  YYYY-MM-DD.json     │
                              │  committed to repo   │
                              └──────────┬───────────┘
                                         │   workflow_run trigger
                                         ▼   redeploys Pages
                              ┌──────────────────────┐
                              │  GitHub Pages        │
                              │  static deploy       │
                              └──────────┬───────────┘
                                         ▼
                                  Browser fetches
                                  today's puzzle
```

The pipeline never blocks: every external dependency (Gemini, the embedding model, even the `wordfreq`/`better-profanity` libraries) is optional. If any one of them fails or isn't installed, the script falls back to a deterministic SHA-256-of-date pick from a curated answer list (Purdle) or a hand-crafted set of backup puzzles (Quartet), so the site always has a puzzle to serve.

## The validation pipelines

Each game's pipeline runs the same retry-with-feedback loop but with checks tuned to its puzzle shape.

### Purdle (single 5-letter answer)

| Check | Library | Reject when |
|---|---|---|
| Format | stdlib regex | Not exactly five lowercase letters |
| Recency | stdlib | Appeared in the last 30 puzzles |
| Curated dictionary | stdlib | Not in `scripts/answer_list.txt` |
| Profanity | `better-profanity` | Flagged as a slur or vulgarity |
| Frequency | `wordfreq` | Zipf score < 3.5 (too obscure) |
| Novelty | `sentence-transformers` | Cosine similarity > 0.75 vs any of the last 30 solutions |

### Quartet (16 words → 4 themed groups)

| Check | Library | Reject when |
|---|---|---|
| Shape | stdlib | Not exactly 4 groups of 4 words; tiers 1-4 not all present |
| Word format | stdlib regex | Not 2-12 lowercase letters; duplicates across groups |
| Profanity | `better-profanity` | Any word flagged |
| Frequency | `wordfreq` | Any word's Zipf score < 3.0 |
| Theme recency | stdlib | Theme reused in last 30 puzzles |
| **Cluster cohesion** | `sentence-transformers` | Mean intra-group cosine similarity < 0.20 *(group's words don't actually cluster)* |
| **Cluster separation** | `sentence-transformers` | Centroid-to-centroid similarity > 0.65 between any two groups *(themes overlap too much)* |

The Quartet cluster check is the headline ML technique on top of what Purdle did with single-word novelty: it validates **structural** properties of the LLM's output, not just per-word ones. When Gemini generates a Quartet whose "groups" don't actually cluster in semantic space (i.e. the puzzle would be unsolvable or unfair), the rejection reason gets fed back into the next prompt attempt.

When all attempts fail, the script logs a warning and writes a fallback puzzle. The site never serves nothing.

## In-game ML (client-side)

| Game | Feature | Technique |
|---|---|---|
| Purdle | "Solver hint" button shows the entropy-maximising next guess | Brute-force [`expectedInfoGain`](src/games/purdle/lib/solver.ts) over the ~14k valid-guess list against the filtered candidate set; precomputed `SALET` opener (≈5.88 bits) for instant turn-1 feedback |
| Quartet | (planned) Suggest the next pick most semantically tied to current selection | Cosine similarity over per-puzzle word embeddings shipped alongside the JSON |

Both run **entirely in the browser**, no server round-trip — the math is auditable and the API budget is zero.

## Tech stack

| Layer | Choice |
|---|---|
| Frontend | React 19 + Vite + TypeScript (strict), React Router 7 |
| State | Zustand with `persist` middleware. Per-game store factory + React-context provider so the same UI works for both the persisted "today" instance and ephemeral archive replays |
| Auth & cloud sync | Supabase (Google / GitHub OAuth), Postgres + Row Level Security per user. Opt-in; gracefully degrades to local-only when the env vars aren't set |
| Styling | CSS variables + tokens, no UI framework |
| Tests | Vitest — [`evaluate.test.ts`](src/games/purdle/lib/evaluate.test.ts) covers the duplicate-letter algorithm + hard-mode rule; [`solver.test.ts`](src/games/purdle/lib/solver.test.ts) covers entropy / pattern grouping |
| Pipeline | Python 3.12, Gemini 2.5 Flash-Lite, `wordfreq`, `better-profanity`, `sentence-transformers` |
| CI / Cron | GitHub Actions (unlimited minutes for public repos) — `daily-puzzle.yml` (Purdle), `daily-quartet.yml` (Quartet), `deploy.yml` triggered by both |
| Hosting | GitHub Pages |

Total runtime cost: **$0** (Pages free + Actions free + Gemini Flash-Lite free tier + Supabase free tier).

## Run locally

### Frontend

```powershell
npm install
npm run dev          # http://localhost:5173/Purdle/
npm test             # Vitest — 31 tests
npm run build        # tsc --build && vite build
```

### Pipelines

Both generators run without any Python deps using their deterministic-fallback path — useful for local development:

```powershell
python scripts/generate_puzzle.py --date 2026-05-06
python scripts/generate_quartet.py --date 2026-05-06
```

For the full LLM-driven pipeline, set up a venv and provide a Gemini API key:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r scripts/requirements.txt
$env:GEMINI_API_KEY = "<your-key>"
python scripts/generate_puzzle.py --date 2026-05-06 --force
python scripts/generate_quartet.py --date 2026-05-06 --force
```

Get a free Gemini key at https://aistudio.google.com/apikey. Free tier (≈ 1,000 RPD on Flash-Lite) is well over what these pipelines need.

### One-time setup

```powershell
.\scripts\download_word_lists.ps1   # Purdle answer list + valid-guess dictionary
```

If you want cloud-synced stats, also create a Supabase project and apply both SQL migrations from `supabase/migrations/`. The repo's `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` GitHub Actions secrets feed those values into the build at deploy time.

## Repo layout

```
src/games/purdle/             # Purdle game (Wordle-style 5-letter)
src/games/quartet/            # Quartet game (16 words → 4 groups)
src/shared/                   # game-agnostic platform shell:
                              #   Header, Modal, settings store, auth store,
                              #   Supabase client, date helper
src/pages/                    # platform-level routes:
                              #   Home, NotFound, archive + replay per game
public/puzzles/<game>/<lang>/ # daily puzzle JSON + manifest (committed by cron)
public/words/                 # valid-guess dictionary + answer list (Purdle solver)
scripts/                      # generators + bootstrap + word-list downloader
supabase/migrations/          # 0001 wordle_stats, 0002 quartet_stats
.github/workflows/            # deploy.yml + daily-puzzle.yml + daily-quartet.yml
```

### Adding a new game

The shell is designed to host more games. To add e.g. a crossword:

1. Create `src/games/crossword/` with its own page, components, store factory, types.
2. Add `/crossword`, `/crossword/archive`, `/crossword/archive/:date` routes in `src/App.tsx` and the corresponding modal switch in the route-aware `Shell`.
3. Build a parallel `scripts/generate_crossword.py` that writes to `public/puzzles/crossword/<lang>/<date>.json` (the `lang` field on the puzzle schema is forward-compatible — additional languages slot in as `crossword/es/`, etc.).
4. Add a sibling `daily-crossword.yml` workflow and add it to the `workflow_run` trigger in `deploy.yml`.
5. (Optional) `supabase/migrations/0003_crossword_stats.sql` mirroring the existing patterns.
6. Add a card to `src/pages/Home.tsx`.
